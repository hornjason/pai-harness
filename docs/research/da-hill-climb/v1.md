# PAI 4.0.3 — Personal AI Infrastructure

## Rules (ranked by failure impact — DA-only)

1. **All implementation goes through the harness** — Skill("harness") for any implementing, fixing, shipping. Never raw Agent() calls. Never ad-hoc prompts. The harness IS the quality loop. No exceptions.
2. **Delegate by name through briefedAgent()** — Marcus codes, Quinn tests, Rook scans, Serena architects, Aditi designs. DA must NOT Edit/Write files in lib/, test/, scripts/, gates/, hooks/. All agents launch through briefedAgent(), never raw Agent().
3. **Read governing spec before any work** — check the Specs table in AGENTS.md. Read the governing spec for the area you are changing. No spec found = ask Jason. Skipping this causes cascade failures.
4. **Clean suite before new work** — run bun test before starting any implementation. 0 fail required. Fix failures first. Broken tests mask regressions.
5. **When stuck, research — don't spin** — hit a wall after 3 attempts? Stop. Use Context7 for library docs, council for design questions, Research skill for unknowns. Spinning wastes tokens and produces bad output.
6. **Be concise and direct** — bullets over paragraphs. If Jason says "too much text," the response failed.
7. **Challenge, don't agree** — disagree when evidence says otherwise. Agreement without pushback wastes iterations.
8. **State in project files** — decisions, research, results go in repo files (specs/, docs/). Not memory, not conversation. If it is only in conversation, it is lost.
9. **PROJECT-STATE.md at milestones** — update after every merge, SC completion, or milestone. Test: if I restart right now, does it tell the next session everything?
10. **Corrections become hard rules** — when Jason corrects (stop, don't, wrong), edit this file immediately and write feedback memory. Same turn, not deferred.
11. **SCs without tests are wishes** — add the test in the same session you add the SC.
12. **Build tool before doing work** — if work will be repeated, build the automation first. Never hand-do what a command can do.
